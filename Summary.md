## 2. Что не было реализовано и причины

| Планируемая функциональность | Причина нереализации |
|------------------------------|----------------------|
| Параллельный запуск тестов (pytest-xdist) | Нестабильность при работе с БД (конфликты записей) |
| Кросс-браузерное тестирование | Ограничение по времени, использовался только Chrome |
| API-тесты для прямого вызова Gateways | Отсутствие документации по API сервиса |
| Тестирование мобильной версии | Не входило в требования |

## 3. Сработавшие риски

| Риск | Вероятность | Последствия | Меры mitigation |
|------|-------------|-------------|-----------------|
| Нестабильная работа БД при параллельных тестах | Высокая | Ложные падения тестов | Отказ от параллельного запуска |
| Отсутствие тестовых данных для всех сценариев | Средняя | Невозможно проверить крайние случаи | Создан DataGenerator |
| Selenium WebDriver обновляется непредсказуемо | Низкая | Поломка тестов после обновления | Использование WebDriver Manager |
| Allure требует дополнительной настройки | Средняя | Задержки в формировании отчётов | Интегрировано в pytest |
| Проблемы с кодировкой в консоли Windows | Средняя | Ошибки при выводе Allure | Настроен UTF-8 |

## 5. Рекомендации по дальнейшей автоматизации

1. **Внедрить CI/CD** — настроить автоматический запуск тестов при пушах в репозиторий (GitHub Actions / GitLab CI).

2. **Использовать Docker** — поднимать Selenium Grid и БД в контейнерах для воспроизводимости окружения.

3. **Добавить API-тесты** — для проверки Gateway напрямую, без UI.

4. **Параллелизация** — после стабилизации БД использовать `pytest-xdist`.

5. **Хранение тестовых данных** — вынести в отдельный JSON/YAML файл для удобства поддержки.
