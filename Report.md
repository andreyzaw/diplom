# Отчёт о проведённом автоматизирован тестировании

## 1. Краткое описание

**Объект тестирования:** Веб-сервис по покупке туров с двумя способами оплаты:
- Оплата по дебетовой карте
- Выдача кредита по данным банковской карты

**Цель тестирования:** Проверка корректности работы форм оплаты и кредита, валидации полей, взаимодействия с базой данных и обработки банковских ответов (Approved/Declined).

**Инструменты автоматизации:**
- **Pytest** — фреймворк для запуска тестов
- **Selenium WebDriver** — управление браузером
- **Allure** — формирование отчётов
- **Python 3.10+**

**Объём тестирования:** Функциональное тестирование позитивных и негативных сценариев, тестирование базы данных.

## 6. Общие рекомендации

### По улучшению качества приложения

1. **Унификация валидации** — привести к единому стандарту проверку полей на обеих вкладках (оплата/кредит).

2. **Улучшение сообщений об ошибках** — сделать их более информативными для пользователя (например, "Месяц должен быть от 01 до 12").

3. **Исправление CVC-валидации** — значения "000" и "001" должны корректно отклоняться.

4. **Доработка интеграции с БД**:
   - Гарантировать создание записей при любом статусе платежа
   - Обеспечить корректные связи между `order_entity` и `payment_entity`/`credit_request_entity`
   - Исправить сохранение суммы (45 000, а не 4 500 000)

5. **Добавить end-to-end тесты** на полный цикл покупки тура.

6. **Пересмотреть обработку отказа** — как по дебету, так и по кредиту должно появляться понятное пользователю уведомление.

## 7. Вывод

Тестирование выявило **16 критических и средних дефектов**, связанных в первую очередь с:
- отсутствием уведомлений при отказе в платеже/кредите (BUG-01, BUG-03),
- некорректной записью в БД (BUG-02, BUG-07, BUG-08),
- ошибками валидации полей (BUG-04–BUG-06, BUG-09–BUG-14).

**Процент успешных тестов — 69.23%** (36 из 52).  
Основной позитивный функционал (approved-сценарии) работает корректно, однако пограничные и негативные сценарии обрабатываются неудовлетворительно.

**Рекомендация:**  
Приложение **не готово к релизу**. Необходимо исправить все критические баги (BUG-01, BUG-02, BUG-03, BUG-07, BUG-08) и большинство нормальных багов валидации перед выкаткой в продуктивную среду.
